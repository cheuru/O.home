# R 대사 CSV

터미널 속 관리 프로그램 **R**의 대사가 들어 있는 폴더입니다. CSV를 고쳐서 GitHub에 올리면 Vercel이 다시 배포하면서 사이트에 반영됩니다.

## 쓰는 법
1. 엑셀(또는 구글 시트)로 CSV를 열어 행을 추가·수정합니다.
2. 저장할 때 **「CSV UTF-8(쉼표로 분리)」** 로 저장합니다. 그냥 「CSV」로 저장하면 한글이 깨집니다(빌드가 멈추고 안내가 나옵니다).
3. 고친 파일을 GitHub 저장소의 `data/r-dialogue/` 에 올립니다. 끝입니다.
   - 내 컴퓨터에서 확인하려면 `npm run dev` (실행할 때마다 CSV를 다시 읽습니다).
   - 변환만 따로 하려면 `npm run r-dialogue`.

## 알아둘 점
- 어떤 파일이 코드에 연결되어 있는지는 **`00_안내.csv`의 「코드 연결」 열**에 적혀 있습니다. 지금은 모든 파일이 연결되어 있고, 「발동 조건」처럼 설명용인 열만 고쳐도 반영되지 않습니다.
- `03`·`05`·`08`·`09`·`10` 의 **「코드 키」 열**은 코드가 어느 줄인지 찾는 이름입니다. 바꾸거나 지우지 마세요(틀리면 빌드가 멈추고 알려 줍니다). 일부러 연결하지 않을 줄은 「참고」라고 적습니다.
- `05b`·`07c` 의 정규식은 `/패턴/` 형태로 적고, `g`·`y` 플래그는 쓸 수 없습니다.
- `01`·`02`·`04` 는 **위쪽 행이 우선**입니다. 키워드가 겹치면 위에 있는 대사가 나옵니다.
- 키워드가 여러 개면 `|` 로 구분합니다. 영어 키워드는 낱말 단위로만 감지됩니다(this 안의 hi는 안 잡힘).
- `06c`(꼬투리 시작 조건)는 R의 **대사 글자**를 보고 대화 트리를 시작합니다. 연결된 R의 대사를 고치면 패턴도 같이 고쳐야 합니다. 안 맞으면 빌드 로그에 「주의」가 나옵니다.
- CSV에 문제가 있으면(없는 노드 연결, 잘못된 카운터 이름 등) 몇 번째 줄이 문제인지 알려 주고 배포가 멈춥니다. 기존 사이트는 그대로 유지됩니다.
- `src/components/desktop/rDialogueData.generated.ts` 는 자동 생성 파일이라 직접 고치지 않습니다.
